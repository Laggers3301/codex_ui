# LaTeX 编辑与 PDF 定位

## 工作区和编译

确定实际主 `.tex`、包含文件、`.bib`、图片和已有构建配置。沿用现有文档类、编译引擎和引用系统，不为了方便把期刊模板改成 `article`。只检查与当前修改有关的依赖。

有宿主编译 API 就沿用它。否则检查既有 `latexmk` / pdfTeX / XeTeX / LuaTeX 是否可用及是否有合适的隔离环境。常规论文可用 `latexmk` 管理多轮编译及 bibliography，但不能直接运行用户上传的 `.latexmkrc`。关闭 shell escape 不能替代文件系统、网络和资源隔离；缺少隔离条件时不要执行不受信任的文档构建。

编辑现有源码时保留宏、标签和跨文件结构。不要改写全篇或重编号来修复单个段落。修改引用前检查对应 `.bib` 项，不自动补不存在的 DOI 或书目信息。

编译任务绑定源文件快照/版本，过期任务结果不能覆盖较新的 PDF。已有宿主自动编译时避免再启动独立文件监听器或重复编译循环。失败时保留最后一次成功 PDF，并明确它对应旧版本。

## 选中 PDF 修改源码

已有 PDF 不意味着有可用源码映射。检查编译时是否保存了匹配版本的 `.synctex.gz`，宿主是否提供页坐标转换和反向 SyncTeX。

有映射：使用页码和正确坐标空间定位源码附近行，再检查选中文字与周围段落；宏展开、重复内容、连字、公式和图注可能需要进一步确认。SyncTeX 不是精确的逐字符编辑映射。

没有映射：结合用户给出的文字和源码检索定位；扫描 PDF、外来 PDF 或不存在的源码不能假称能够直接回改原 LaTeX。可以协助重建内容，但必须与修改原稿区分。

## 检查

只编译实际相关入口，检查新增错误、未解析引用和丢失资源。用户要求版式或数学排版验收时渲染相应页面比较；不要仅凭编译退出码宣称排版完全一致。

交付修改过的源文件及用户要求的 PDF，不把整个工作区、凭据或无关缓存一起打包。
