# LaTeX 与 DOCX 转换

## 交付约定

转换默认生成副本，原生主文件保持不变。LaTeX → DOCX → LaTeX 不是恢复原始源码的方法；宏、文档类、分页和布局不能保证往返一致。用户明确选择主文件迁移时保留原稿与资源，并说明具体未保留项。

把三种目标分开：内容/结构正确、排版相近、可编辑性。不能用整页截图嵌入 Word 来冒充可编辑无损转换，也不能因为文字完整就宣称排版无损。

## 可用转换路径

已有 Pandoc 时先试 LaTeX reader → DOCX writer，配合真实 `.bib`、CSL 和用户指定的 `reference.docx`。参考模板控制 Word 样式及页面属性，不会复刻 LaTeX 文档类。不要自动执行上传文档附带的 Lua/Python filter 或 LaTeX 宏命令。

支持的数学表达式可以转为 OMML；自定义宏、复杂多行公式、TikZ、算法环境、合并表格和特殊期刊 front matter 必须核对。转换警告不是完整的丢失检测：某些结构可能没有对应表示而被忽略。

不支持的内容先列出来。必要时为明确的文档类/宏添加有限转换规则；图形可预渲染成图像，但这会失去原生可编辑性。不能静默删除图形或把失败公式当普通文本交付。

TeX4ht/make4ht 的 ODT 路线可以按实际失败案例比较，但 ODT → DOCX 还会多一次转换。LaTeXML 是语义 XML/HTML 等输出路径，不是现成的无损 DOCX 转换器。没有证据支持更好时不要为了探索再安装多套引擎。

## 校验覆盖

按文档实际包含的内容检查：标题与段落、图片/图注、公式及编号、表格、脚注、引用和交叉引用。检查转换后的公式是否为 OMML，引用是否有未解析条目；不把格式化引用文字当成 Zotero 等动态引用域。

在可用 Word/Office 渲染器中打开输出，核对重要页面；必要时对原稿 PDF 做并排比较。逐项说明保留、降级和未支持项，不宣称未经测试的完整保真。

DOCX → LaTeX 应恢复可表达的正文/公式并生成新的源文件，不承诺恢复原文档类、宏定义或原先的换行布局。需要从 Word 外观编辑原 `.tex` 的流程，必须额外维护经过验证的源范围映射，不能用两次普通转换代替。
